WHAT CHANGED (summary; details in the response file)
- Identity (class A): a hybrid account is accepted only at the SimpleFactory CREATE2 address of the canonical ERC1967Proxy
  initialised with (owner, no P256 keys) under the fixed salt; owner() is a candidate that must re-derive the address; the
  treasury / fee recipient can never be owners; the owner is pinned. A 7702 account is recognised from its designator.
  live() re-checks designator / owner on every keeper action. onboard pulls only from the pinned owner.
- Transfers out (A): verified at the recipient (balance delta) plus a directional post-check at the account; decreases /
  burns also check that the account value at the pool price did not fall beyond rounding.
- Flow booking (B): SALib.sync books and re-snapshots in one step; every path calls it; returns are bracketed live or not.
- Delegation (C): one stored delegation; replacing it or resuming after revoke() needs the account or its pinned owner;
  caveat args empty; expiry <= uint64; enforcer state per (delegator, terms hash).
- Value (D): positions at principal(sqrt price) + uncollected fees; no pool-spot term; sends and fees need a fresh,
  unclipped anchor within the pool band; the fee also needs a recent unclipped hedge report.
- Budgets (E): SAWindow for turnover, hedge step, anchor drift, enforcer hedge limit; 1x in any 24 h window.
- Approvals (F): one-shot, TTL <= 1 day, hedge approvals bound to (account, epoch, stored value, value, guardian era).
- Treasury / pause (G): keeper return <= the account's hedge equity, always into the account; pause stops margin sends and
  keeper-only equity cuts; roles pairwise distinct.
- Exit (H): revoke(account) (no external calls, not pausable) + an ERC-7579 TRY-mode exit batch, checked by state.

TASK 1: VERIFY THE ROOT-CAUSE CLAIMS
For each class A-H in docs/audit/sa_round1_rootcause.md:
1. Is the stated invariant actually enforced by the code at {{COMMIT}} on EVERY path, not just on the path of the original
   finding? Give a counter-example trace if not.
2. Is the invariant the right one (would a fix of the invariant as stated have prevented the original finding AND its
   siblings), or is it too narrow?
3. Did the structural change introduce a new problem (liveness, griefing, a check that blocks the client's own exit or a
   risk-reducing keeper action, a budget that can be exhausted by a third party)?
Specific claims to try to break:
- "The CREATE2 address commits to the implementation, the owner and the absence of P256 keys at creation, so owner() is
  checked, not believed" (SALib.accountKind / hybridAddress). Consider: initcode variants, salt, factory, an account the
  owner upgraded after creation, an owner() that reverts / returns oddly / consumes gas.
- "Whatever client code does inside a module action can only make the books more conservative" (post-checks, value
  conservation on removals, subscribers refused). Consider adds (mint / increase), swaps, native HYPE receive, fee collect.
- "sync owns the snapshot": find any path that writes snapAsset / snapBase / snapLiquidity without booking, or books
  without re-snapshotting.
- "Any 24 h window admits at most 1x the cap" (SAWindow): bucket boundaries, the ring overwrite, credit(), amounts above
  2^96, block.timestamp jumps.
- "A guardian approval applies only to the state the guardian judged": epoch / era / stored value, refused reports,
  multicall ordering, approvals made in the same block as a margin move.
- "revoke() cannot fail for the account itself": for both account kinds, with the module paused, the DM paused, a hostile
  subscriber, many positions, an EntryPoint that swallows failures.

TRUST MODEL AND ROLES (unchanged from round 1, except where noted)
- client: owns the account, every token and position NFT; can act directly; stops management with revoke() or by
  disabling the delegation; only the client can resume.
- module owner = VaultTimelock (48 h default, floor 24 h): keeper / guardian rotation, params within hard caps, unpause.
- keeper (hot key): every module action within the on-chain budgets; never submits raw executions; may return at most an
  account's own hedge equity.
- guardian: pause (stops mints, increases, swaps, fees, margin sends, anchor movement and keeper-only equity cuts; never
  decreases, burns, returns or client actions), one-shot price ranges and per-account hedge-equity approvals.
- relayer: deploys accounts, first registration and onboard (permissionless).
- hedgeTreasury / feeRecipient: operator addresses, immutable, distinct from every role.
